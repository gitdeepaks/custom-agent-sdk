# Releasing To npm

Releases are generated by Release Please and published from
`.github/workflows/release.yml`. The first releases use the `next` npm tag.

## One-Time npm Setup

1. Sign in to npm and confirm that your account owns or belongs to the
   `deepaksankhyan91` organization. The package is published as
   `@deepaksankhyan91/open-agent-sdk`.
2. Ensure the organization allows public packages and requires two-factor
   authentication for account changes.
3. After the package exists, configure npm Trusted Publishing for:
   - GitHub organization or user: `gitdeepaks`
   - Repository: `custom-agent-sdk`
   - Workflow: `release.yml`
   - Environment: `npm`
4. In GitHub, create an `npm` environment and require maintainer approval.
5. Protect `main` and require the CI release-gates job before merge.

The workflow uses GitHub OIDC and npm provenance. Do not add an `NPM_TOKEN`
unless npm requires a token for the one-time bootstrap publish.

## Local Verification

```bash
bun install --frozen-lockfile
bun run check:release
```

`verify:package` builds the exact tarball, installs it in an isolated Bun and
TypeScript consumer, tests all public entry points, and rejects sensitive or
repository-only files.

## Release Flow

1. Merge conventional commits into `main`.
2. Review and merge the Release Please release pull request.
3. Approve the protected `npm` GitHub environment deployment.
4. Confirm the package provenance and install the registry artifact:

```bash
bun add @deepaksankhyan91/open-agent-sdk@next
npm install @deepaksankhyan91/open-agent-sdk@next
```

When the prerelease is proven stable, remove `prerelease` and
`prerelease-type` from `release-please-config.json`. The next release will be
published with the `latest` tag.

## Scope Fallback

The original `open-agent` npm organization is not controlled by this project.
Do not change the package back to that scope without verified organization
membership and publishing access.
